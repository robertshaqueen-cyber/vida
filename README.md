# vida

**加密金库 + 主机管理，正在长成一个 AI Agent 可直接操作的终端。**

vida 解决两个问题：

1. **主机凭据安全**：所有 SSH 主机、口令、私钥存进一个 age 加密的金库（`vault.age`），
   标准 `age` CLI 即可解密，支持本地文件夹同步（Dropbox/Syncthing 友好）。
2. **让 AI Agent 直接操作你的主机（规划中，M5）**：将内置 MCP 服务端，
   让 AI 编码助手（Claude Code、Cursor 等）可以通过 MCP 协议读写金库、连接主机，
   无需把凭据喂给任何第三方。

## 当前状态

**早期开发中。** 已实现：加密金库、本地路径同步、主机管理界面、
**本地终端核心（M2a）**以及**正式终端标签（M2b-3）**——多 PTY 会话、
二进制增量推送、GPU 渲染、键盘/IME/安全粘贴、窗口 resize 和断线重连；
**SSH 终端（M3）**已接入系统 OpenSSH，支持金库口令、私钥文件和导入私钥。
**会话恢复（M4）**使用独立会话宿主持有 PTY/SSH，daemon 崩溃或重启不再结束 shell。
**Agent 控制层（M5，进行中）**已提供共享 daemon 客户端、`vidactl`、daemon 侧主机信任
策略、危险命令审批、不含命令明文的审计，以及 GUI 实时审批与人工接管；MCP Server
仍在后续检查点中。

## 安全说明（重要）

**项目处于早期开发阶段，未经第三方安全审计。不建议存放生产环境关键凭证。**

### 威胁模型

**保护什么：**
- 文件被拷贝走：无主口令无法解密金库内容
- 云盘服务商：同步文件夹中的密文不可读
- 口令缓存：仅选择有限记住时长时写入系统钥匙串，最长 7 天

**不保护什么：**
- 主机数据（名称/地址/端口/用户名）在金库解密后可见 ——
  金库文件本身是加密的，但解密后这些字段不额外加密
- 已解锁状态：金库内容驻留内存，具备本机权限的进程理论可读取
- 主口令丢失：数据永久丢失，无后门、无恢复通道
- 本机恶意软件：攻击者获得你的用户级权限后，可读取解锁后的内存

### 安全措施（具体做法，非绝对保证）

- 密码与私钥内容永不写入日志
- 敏感字段使用 zeroize 在 drop 时清零
- 金库写入采用原子写入 + fsync，避免半写状态
- `daemon.token`（WebSocket 认证）权限 0600

详细说明见 [SECURITY.md](SECURITY.md)。漏洞上报请走
[GitHub Security Advisory](https://github.com/robertshaqueen-cyber/vida/security/advisories/new)，
不要使用公开 Issue。

## 架构

```
vida (GUI) ──────┐
vidactl ─────────┼── vida-client ──WebSocket──▶ vida-daemon (金库/同步/协议)
vida-mcp (M5) ───┘                                ├── 金库 (vault.age, age 加密)
                                                 └── 本机 0600 IPC ──▶ vida session host (PTY/SSH)

AI Agent ──MCP stdio(规划 M5 后续检查点)──▶ vida-mcp
```

- **vida-core** — 金库、加密、同步、多语言（纯逻辑库）
- **vida-client** — GUI、CLI、MCP 共用的 daemon 发现、认证、请求关联和推送客户端
- **vida-daemon** — 守护进程：WebSocket 服务端、协议路由、状态管理
- **vida-gui** — iced + wgpu 原生界面
- **vida-mcp-cli** — 产出 `vidactl`；后续也产出 MCP stdio 入口 `vida-mcp`

## 构建与运行

**前置依赖：**

- Rust 工具链（stable）
- `age` CLI —— 互操作测试（`age_cli_interop`）会真实调用标准 age
  解密金库，验证「软件停止维护后数据仍可用标准工具解密」
- `expect` —— age CLI 的交互式口令提示需要 TTY，测试用 expect 驱动

```bash
# macOS
brew install age expect

# 构建
cargo build --release

# 启动 daemon（第一个终端）
cargo run --bin vida-daemon

# CLI（另一个终端）
cargo run -p vida-mcp-cli --bin vidactl -- doctor
cargo run -p vida-mcp-cli --bin vidactl -- host list
cargo run -p vida-mcp-cli --bin vidactl -- session list
cargo run -p vida-mcp-cli --bin vidactl -- session screen <session-id>

# Agent 安全写入：普通命令直接发送，危险命令返回待审批 ID
cargo run -p vida-mcp-cli --bin vidactl -- session exec <session-id> -- df -h
cargo run -p vida-mcp-cli --bin vidactl -- session exec <session-id> -- rm -rf /tmp/example
cargo run -p vida-mcp-cli --bin vidactl -- approval list
cargo run -p vida-mcp-cli --bin vidactl -- approval deny <approval-id>
cargo run -p vida-mcp-cli --bin vidactl -- audit --limit 20

# 脚本使用稳定 JSON envelope
cargo run -p vida-mcp-cli --bin vidactl -- --json status

# 启动 GUI（第二个终端）
cargo run --bin vida

# 运行测试（需要 age + expect）
cargo test --workspace
```

> 没有安装 age/expect 时，`age_cli_interop` 测试会**失败**（而不是跳过）——
> 这是有意为之：该测试是设计铁律「金库必须可用标准 age CLI 解密」的唯一验证。

## M2b-3 手动验收

启动 daemon 和 GUI，解锁后点击顶部终端按钮：

1. 点击终端画面，输入 `echo hello` 并按 Enter → 预期看到 `hello`。
2. 输入 `sleep 30`，按 Ctrl+C → 预期立即回到 shell 提示符。
3. 按方向键上再按 Enter → 预期重新执行上一条命令。
4. 从其他应用复制两行中文命令，回到终端按 Cmd+V（Linux/Windows 为 Ctrl+Shift+V）
   → 预期两行只进入编辑缓冲区，不立即执行；按 Enter 后才执行。
5. 切换中文输入法，在终端输入中文并确认候选 → 预期中文进入命令行，候选窗位置跟随光标。
6. 调整窗口大小，再执行 `stty size` → 预期行列数随窗口改变，文字不拉伸、不裁切。
7. 回到终端提示符静止两秒 → 预期当前输入位置的实心方块光标每 500ms 明暗切换。
8. 执行 `ls` 查看中文文件名 → 预期中文字形保持正常宽高比，不被横向拉扁；
   连续输出多行时各行互不遮盖；默认内置 JetBrains Mono 13pt，行高约 15px；
   中英文均由 iced 原生文字管线绘制，英文笔画完整，中文高度与英文协调且边缘平滑。
9. 在提示符输入但先不要执行 `ls --color` → 预期两个 `-` 都清晰可见；按回车后，
    同一行的字形粗细和颜色不应突然变白或变粗。
10. 切换到「设置 → 终端」→ 预期字体和字号都是下拉选择；字体列表含
    内置 JetBrains Mono 与系统安装的等宽字体。修改任一项并保存，再打开终端 → 预期新设置生效；
    重启 Vida 后仍保持。
11. 连续点击两次顶部终端按钮 → 预期出现“本地终端 1”和“本地终端 2”两个正式标签；
    分别执行 `echo first` 和 `echo second`，来回切换后各自只保留自己的输出与命令历史。
12. 在终端 1 执行 `sleep 5; echo kept`，立即切换到主机、设置或终端 2 → 预期终端 1
    在后台继续运行；5 秒后切回能看到 `kept`。
13. 关闭终端 1 标签 → 预期只关闭终端 1 的 PTY，终端 2 仍可正常输入；关闭当前标签后
    自动选择相邻标签，不跳回列表最前端。
14. 同时打开本地和 SSH 终端后点击锁定 → 预期 daemon 中的 PTY 被安全关闭，但标签布局被
    保留；重新解锁后在原标签恢复相同类型的终端，成功后不再残留“断开/重新建立”提示。
15. 终端打开时停止 `vida-daemon`，等待 Vida 显示断线提示后再启动 daemon → 预期 Vida
    持续自动重试并进入金库解锁页，不需要点击锁定；解锁后原标签订阅原 session id，
    断线前的画面、工作目录、环境变量和运行中命令都还在，不创建替代 shell。
16. 执行 `seq 1 200`，在终端区域向上滚动鼠标滚轮或触控板 → 预期浏览 daemon 保留的
    真实回滚历史；新输出到达时当前阅读位置不被强制拉回底部，键盘输入时回到底部。
17. 在终端中按住鼠标左键跨行拖动 → 预期出现青绿色选区；按 Cmd+C
    （Linux/Windows 为 Ctrl+Shift+C）后粘贴到其他应用 → 预期得到所选文字，行尾空白不混入；
    保持选择并用滚轮跨过当前屏幕后选区不会丢失，继续选择并复制可包含跨屏历史内容。
18. 在终端中点击右键 → 预期出现与 Vida 深色界面一致的“复制/粘贴”菜单；没有选区时
    “复制”置灰，有选区时可复制；鼠标进入菜单后切换为普通箭头，经过可用菜单项时
    对应整行高亮；“粘贴”仍通过安全的 `PasteSession` 路径进入终端。

## M3 SSH 终端手动验收

启动 daemon 和 GUI 并解锁金库，准备一台可测试的 SSH 主机：

1. 打开主机详情并点击“连接” → 预期创建以主机名命名的终端标签，并进入远端 shell；
   从顶部快速连接面板点击同一主机也应直接创建 SSH 标签，而不是只切换资料页。
2. 使用“口令”认证的主机执行 `hostname` 和 `whoami` → 预期输出来自远端主机，连接过程
   不要求在终端中再次输入已保存在金库里的口令。
3. 新增主机时把认证方式改为“私钥文件”，选择本机私钥并按需填写私钥口令 → 预期连接成功；
   编辑该主机但不修改认证区域并保存 → 预期原凭据保持不变。
4. 新增主机时选择“导入私钥”，从系统文件窗口导入私钥并按需填写私钥口令 → 预期连接成功；
   关闭 SSH 标签或锁定金库后，应用私有 `ssh-keys` 目录中不应遗留对应临时 `.key` 文件。
5. 首次连接未记录过主机密钥的服务器 → 预期系统 OpenSSH 采用 `accept-new` 写入用户的
   `known_hosts`；把测试服务器密钥更换后再次连接 → 预期 OpenSSH 明确拒绝连接并显示
   `REMOTE HOST IDENTIFICATION HAS CHANGED`，不会静默覆盖旧密钥。
6. 将口令或私钥口令故意改错后连接 → 预期终端显示 OpenSSH 的认证失败原因且会话结束；
   状态区不得只显示 `exit_code=255`，而应说明可能原因并提供“编辑主机”按钮；Vida 的
   daemon 日志中不得出现口令、私钥内容或其文件内容。
7. SSH 标签中验证中文输入、Cmd+V 安全粘贴、鼠标滚动、拖动选择、右键复制/粘贴和窗口 resize
   → 预期与本地终端行为一致，且输入直接进入远端 PTY；复制多行 `ps aux` 输出再粘贴时，
   即使远端 shell 未开启 bracketed paste，各行也只会折叠在当前输入行，不得立即逐行执行。
8. 同时打开两个本地终端和两个 SSH 终端，分别执行不同命令并切换标签 → 预期四个会话互不串台；
   关闭一个 SSH 标签只结束对应连接，点击锁定则关闭全部终端。
9. SSH 标签打开时停止 daemon，看到断线提示后再启动 daemon → 预期 GUI 持续自动重试，
   新 daemon 即使尚未解锁金库，也直接重新订阅 session host 中的原 SSH session，
   不得跳到解锁页；远端 shell、当前目录和运行中命令不变，也不会再次发起 SSH 认证。
10. 将主机地址设为以 `-` 开头、用户名设为 `-V` 或端口设为 0 后尝试连接 → 预期 Vida 拒绝
    无效配置并给出可读提示，内容不会被解释为额外的 `ssh` 命令行选项。
11. 关闭主机资料标签，进入“设置 → 配置和连接” → 预期每台主机仍显示“连接”和“编辑”按钮；
    点击“编辑”可重新打开编辑标签，点击“连接”可直接新建 SSH 终端。
12. 打开“新增主机”或“编辑主机”后缩小窗口高度 → 预期表单可用滚轮或触控板向下滚动，
    “保存”和“取消”按钮保持正常高度且可点击；依次按 Tab（反向用 Shift+Tab）→ 预期焦点按
    画面顺序在名称、地址、用户、端口、认证凭据、标签、分组和备注输入框之间移动。

## M4 持久会话手动验收

1. 在本地终端执行 `export VIDA_M4=kept; cd /tmp; sleep 30`，强制结束 daemon 后重新启动
   → 预期 GUI 短暂显示断线；新 daemon 连上后不弹出金库解锁页，直接恢复同一
   标签和 session，`sleep` 继续运行。冷启动 GUI 或主动点击锁定仍必须输入金库口令。
2. 等 `sleep` 结束后执行 `echo "$VIDA_M4:$PWD"` → 预期输出 `kept:/tmp`，证明恢复的不是
   只有画面，而是原 shell 进程及其环境。
3. 在 SSH 标签进入一个非默认目录并运行 `sleep 30`，重复 daemon 重启 → 预期远端命令继续、
   目录不变，且不会再次询问 SSH 口令或私钥口令。
4. daemon 停止期间在终端键入字符 → 预期提示输入未发送，不会在重连后突然补发到 shell。
5. daemon 或 GUI 恢复后 → 预期空闲会话的旧画面和提示符立即出现，无需先按回车；原
   “终端连接已断开”提示消失，滚动历史、选择、复制粘贴继续可用。
6. 主动点击锁定 → 预期这是安全边界：实际 PTY/SSH 被关闭，但标签布局保留；解锁后在原
   标签创建新会话，不应把主动锁定误当作意外 daemon 重启而保留远端 shell。
   依次切换到每个重建的本地终端 → 预期第一张画面和提示符立即出现，无需按回车触发。
7. 关闭所有终端标签并退出 daemon → 预期空的 session host 自行退出；配置目录中的
   `session-host.sock` 消失，不残留无会话的后台进程。
8. 不记住口令时重启 daemon，等原终端无感恢复后关闭原 SSH，再从快速连接点击该
   主机 → 预期自动进入解锁页；输入口令后自动继续刚才的 SSH 连接，不再显示
   “金库已锁定”的死路错误条。
9. 解锁时依次选择“不记住”和“7 天” → 预期不记住时 daemon 重启后新建 SSH 会再次
   要求口令；选择 7 天后 daemon 在有效期内重启可自动解锁，新建 SSH 不再询问。
   主动点击锁定后必须立即撤销该缓存，下次仍要求口令。点击“记住口令”下拉框 →
   预期控件本体及展开菜单与设置页下拉框使用相同的高度、边框、圆角、背景和选中态，
   不出现 iced 默认样式。

## M5a 共享客户端与只读 CLI 手动验收

1. daemon 运行时执行 `vidactl doctor` → 预期显示“可连接、认证成功”、实际配置目录和
   金库状态；不会要求或显示金库口令。
2. 在设置中将界面语言切换为 English，再执行 `vidactl status` → 预期人类可读输出为英文；
   切回中文后预期输出为中文。执行 `vidactl --json status` → 两种语言下都必须保持
   `{"ok":true,"data":...}` 的相同字段结构，且进程退出码为 0。
3. 金库已解锁时执行 `vidactl host list` → 预期只显示主机摘要，不出现保存的密码、
   私钥内容或私钥口令；`vidactl host show <完整 ID 或唯一名称>` 返回对应主机。
4. 同时打开本地和 SSH 终端后执行 `vidactl session list` → 预期列出与 GUI 相同的
   session id、尺寸和进程；执行 `vidactl session screen <session-id>` 显示当前屏幕，
   但不会发送按键或改变终端状态，远端输出不会因 Vida 的界面语言而被翻译。
5. 停止 daemon 后执行 `vidactl doctor` → 预期显示“daemon 可能尚未启动或正在重启”的
   人话提示并以退出码 10 结束；加 `--json` 时仍输出合法错误 envelope。
6. 保持 GUI 打开并重复上述只读命令 → 预期 GUI 的连接、标签、终端内容和输入均不受影响。

## M5b Agent 写入策略、审批与审计手动验收

下面的 `<session-id>` 可由 `vidactl session list` 取得。请先使用临时本地终端或测试主机，
不要拿生产主机试危险命令。

1. 执行 `vidactl session exec <session-id> -- echo vida-agent-ok` → 预期退出码为 0，终端
   出现 `vida-agent-ok`；人的键盘、IME、粘贴路径仍照常工作。
2. 执行 `vidactl session exec <session-id> -- rm -rf /tmp/vida-never-create` → 预期命令不进入
   终端，显示待审批 ID，并以退出码 20 结束。执行 `vidactl approval list` → 预期能看到
   完整待审批命令和 120 秒到期时间。
3. 对该 ID 执行 `vidactl approval deny <approval-id>` → 预期显示已拒绝，终端中没有该命令。
   再创建一条待审批命令并执行 `approval approve` → 预期只有批准后才发送。
4. 等待一条待审批命令超过 120 秒后再批准 → 预期返回“找不到或已过期”，命令不发送。
5. 执行 `vidactl host trust <主机 ID 或唯一名称> readonly`，打开该 SSH 会话后执行安全的
   Agent 命令 → 预期也被拒绝且退出码为 21；改回 `ask` 后安全命令直接发送、危险命令审批。
   `trusted` 会跳过内置危险规则，只应用在明确可完全托管的测试主机。
6. 执行 `vidactl audit --limit 20` → 预期看到时间、session、结果、规则与命令指纹；打开
   Vida 配置目录中的 `audit.jsonl`，确认不含刚才命令的明文、口令或私钥内容。
7. 尝试用 Agent 身份直接调用原始 `SessionInput`（自动集成测试已覆盖）→ 预期 daemon 返回
   `forbidden`；持有 Agent token 也不能修改金库、显示凭据或批准自己的命令。
8. 将现有 v6 金库交给新 daemon 解锁 → 预期自动迁移为 v7，所有主机默认 `ask`，不会因
   升级获得 `trusted`；原主机凭据、备注和连接方式保持不变。

## M5c GUI 实时审批与主机权限手动验收

请保持 GUI 和 daemon 打开，并使用临时本地终端或测试主机。下面的危险命令只用于触发策略，
在批准前不会进入终端。

1. 执行 `vidactl session exec <session-id> -- rm -rf /tmp/vida-gui-approval-test` → 预期 GUI
   立即弹出统一样式的审批面板，显示目标主机/本地终端、session id、完整命令、中文危险原因
   和 120 秒倒计时；终端中没有这条命令。
2. 点击“稍后处理” → 预期面板关闭，顶栏出现带数量的黄色审批入口；点击该入口可重新打开，
   命令和剩余时间保持正确。
3. 同时创建两条待审批命令 → 预期顶栏数量为 2，面板左侧可切换两条命令，选中项和详情一致，
   不会用后一条覆盖前一条。
4. 选择一条点击“拒绝” → 预期该命令从队列消失、显示拒绝结果，终端没有执行；另一条仍在。
   对另一条点击“仅批准本次” → 预期只发送这一条，终端出现对应命令结果。
5. 创建一条待审批命令并等待超过 120 秒 → 预期倒计时变为已过期，daemon 刷新后移除该项，
   命令始终不执行。若审批期间关闭对应终端，预期显示会话结束/命令取消。
6. 在 daemon 停止期间创建不了新审批；重启并恢复 GUI 连接后，若 daemon 内仍有待审批项，
   预期通过列表补偿重新显示，不依赖某一条实时事件恰好到达。
7. 编辑 SSH 主机 → 预期“Agent 命令权限”下拉框与现有输入框样式一致，默认是“危险命令需要
   确认”；保存后重新进入编辑页仍保持。主机详情页也显示当前权限。
8. 把测试主机设为“只读”后执行安全 Agent 命令 → 预期拒绝且 GUI 不出现审批；设为“无需确认”
   后危险命令会直接发送，因此只应在明确可完全托管的测试主机上选择这一项。人的键盘、IME、
   鼠标选择和粘贴在三种设置下都不受影响。

## UI 基础框架手动验收

本轮只改视觉框架与布局，不改变主机、同步、金库和终端的业务语义：

1. 启动 GUI → 预期连接/解锁页显示居中的深色卡片，标题、说明和主按钮层级清楚，
   不再是散落在空白背景上的原生控件。
2. 解锁进入主界面 → 预期顶部是紧凑的深色标签栏；当前标签有明确表面与青绿色状态，
   加号、快速连接、终端、同步、设置、锁定均显示为同一套线性图标。
3. 连续打开多个终端或编辑标签 → 预期标签区域可横向滚动；右侧同步、设置、锁定按钮
   始终留在窗口内，不会被标签挤走；载入主机列表不会自动为每台主机创建标签。
4. 点击快速连接图标 → 预期出现带阴影的居中浮层；搜索、最近主机、全部主机和新增按钮
   层级清晰。点击浮层外部 → 预期关闭浮层。
5. 在“设置 → 配置和连接”按需点击“详情” → 预期只为所选主机打开资料标签；主机身份、
   连接地址、认证方式、分组/标签和备注以卡片分区展示，编辑、显示凭据、删除三个操作明确。
6. 点击设置图标 → 预期左侧为固定导航，当前栏目显示青绿色选中态；右侧内容可滚动，
   每个栏目使用一致的内容卡片、输入框、下拉选择和保存按钮。
7. 点击终端图标 → 预期终端顶部显示紧凑会话栏，关闭按钮位于右上；终端画布占满剩余空间，
   不再在窗口底部显示突兀的“返回”按钮。
8. 分别点击同步、设置、锁定、标签关闭和终端关闭 → 预期仍执行原有功能；图标改造不应
   造成按钮失效或点击区域错位。
9. 在解锁页输入错误口令并点击“解锁” → 预期输入框显示细红边，下方出现淡红色的
   行内错误提示和警告图标；提示不会变成高亮纯红色大框，也不会挤乱表单对齐。
10. 分别打开“新增主机”和“编辑主机” → 预期表单位于统一内容卡片中，标题、说明、
    输入框和按钮与设置页使用同一套样式；输入或清空字段时，保存/取消仍执行原有功能。
11. 点击快速连接 → 预期浮层只有一层边框和一层阴影；底部按钮只显示一个加号和
    “新增主机”，不会出现“+ +新增主机”。
12. 进入“设置 → 配置和连接” → 预期每台主机以横向列表项显示，主机名和
    `用户名@地址:端口` 分两行排列，右侧始终提供“连接、编辑、详情”按钮；中文主机名
    不会被挤成逐字竖排。关闭资料标签后这些入口仍然可用。
13. 通过快速连接打开 SSH 后退出并重新启动 Vida → 预期“最近访问”仍保留；上次未关闭的
    本地/SSH 终端标签按原顺序恢复。若没有保存过终端布局，首次进入主界面只打开一个本地终端。
14. 依次查看“应用、同步、终端、备份/恢复” → 预期各分区始终保留同一套设置侧栏和
    内容卡片；输入框、下拉框、主次按钮及说明文字的边框、间距和状态保持一致；同步页
    的“选择文件夹”与备份/恢复页的“选择备份文件”按钮字号、内边距和高度一致。
15. 点击“设置 → 备份 → 导出备份” → 预期先打开系统保存窗口；选择文件名和目录后，
    备份表单仍在设置内容卡片内，成功提示显示实际完整路径。取消保存窗口则不导出、
    不显示成功；导出的 `.age` 文件可用所选口令通过标准 age CLI 解密。
16. 在“设置 → 备份与恢复”点击“选择备份文件” → 预期取消系统文件窗口不改变当前
    金库；选择 `.age` 后输入错误口令并点击“验证备份”，页面内显示错误且主机列表
    不变。改用正确口令验证后，页面显示备份时间、主机数量和主机名；点击“确认恢复
    并替换当前金库”后，主机列表变为备份内容，重新锁定后可使用该备份口令解锁。
17. 在“设置 → 终端”修改字体、字号或光标闪烁并保存，再打开终端 → 预期设置仍会
    作用于 Vida 使用 iced 原生文字管线绘制的终端内容。
